## 用户流程与验收

1. 从 `Open Canvas` 打开管理窗口，在 `List` 和 `Board` 分别点击 `+ New Note`；另验 ⌘N。查询应清空，新便签应选中并出现正文编辑区。Canvas 新建默认隐藏独立窗口。
2. 点击正文，输入包含换行和中文的合成文本，切换选择后再选回。点击 `Show Window`，确认独立便签可编辑且显示相同内容。
3. 正常关闭单张便签窗口；内容仍在管理窗口中，`Show All Notes` 可重新显示。关闭窗口不等于删除。
4. 正常退出仅用于测试的实例，再启动同一隔离目录。核对文本、颜色、便签 ID 及可见性。不能仅检查进程存在。
5. 对合成便签使用 `Move to Trash on This Mac`，再从 `Restore from Trash on This Mac` 恢复。正文与 ID 保持一致。
6. 对静止的合成资料目录执行整目录备份、验证恢复，再由测试实例读回。整目录回滚与回收站恢复是两个不同操作。

## 完成定义与验收标准

| 验收项 | 必须观察到的结果 | 方法与限制 |
|---|---|---|
| 新建入口 | List、Board 按钮和 ⌘N 均新增一张并选中，能实际点击正文输入 | 真实 GUI；Store 返回 ID 不足以通过 |
| 编辑保存 | 换行、中文、颜色正确；切换便签不丢输入；成功写盘可核验 | GUI 输入加隔离文件断言，不用剪贴板 |
| 正常重启 | 新进程从相同隔离目录恢复内容与身份，并可继续编辑 | 正常退出测试实例；不杀日用实例 |
| 隐藏与回收站 | 隐藏仍可找回；本机删除可恢复；不影响其他便签 | GUI 操作合成便签，不涉及云删除或批量产品决定 |
| legacy/v2 硬链接 | `nlink=2` 可加载、新建、编辑和保存；另一链接字节不变；v2 扩展字段保留 | 现有隔离 Store 回归与新进程读取 |
| v3 硬链接 | 启动只读，拒绝新建；不累积无法保存的草稿 | 真实合成迁移产生 v3 后建立硬链接，仅在隔离目录 |
| 失败与并发 | 写失败保留内存输入并显示错误；重试可保存；其他实例持锁时不绕写 | 现有失败/锁回归；真实错误提示另验 GUI |
| 升级与回滚 | 精确候选身份与来源已核验；静止备份可恢复；替换前后数据完整 | 安装须独立授权和退出条件；启动成功不等于功能验收 |

根 ROADMAP 仅在对应用户闭环和必要交付证据齐全时勾选。编译、自动化、真实 GUI 和安装分别出具证据，不互相替代。已有命令行删除恢复的勾选不能覆盖 GUI 单张删除恢复。

## 产品设计

本轮方向来自用户 2026-10-22 的 Apple 平台一致性要求。保留 Mac 分栏、独立窗口、标题拖动和菜单快捷键，不套用手机导航。已查看用户提供的旧截图 `screenshots/canvas-feedback.png`：旧 Browse 标签换行；当前代码已有隐藏标签及两行工具区，不重复计作新增。该截图不是 0.3.94 最新渲染。已通过 Library materialize 下载并实际查看 `libfile_2a67550ab8948191805c377e6586e2aa`（0.3.91 `image(3).png`）：中央橙色 CLI 提示、双空态及两行工具条均可见。它是修复前证据，不充作改后视觉验收。

当前增量设计（结构示意，非运行截图）：

```text
[List | Board]  [+ New Note]                       [Settings…]
[Search all notes________________] [Window Layout] [Search]
[存储错误：直接显示具体错误与警示图标，仅故障时出现]
[▸ Command-line access unavailable：次级详情，按需展开]
──────────────────────────────────────────────────────────
便签列表 / Board                 │ 所选便签正文
无便签：New Note 主按钮           │ 保留 Mac 分栏编辑
无搜索结果：Clear Search         │ Show / Hide Window
无法写入：Notes Unavailable      │ 不把加载失败当正常空库
```

执行目标：存储故障与空库分开；正常空库可就地新建；搜索无结果可清空；CLI 故障详情收起但可发现；禁写时不提供无效新建按钮。复用 Store 的 localStateWritable，不降低锁或持久化门禁。颜色/字号沿用原生语义样式。未改导航形态、同步、批量语义。

交付前必须由我们先验完整用户路径、视觉交互、持久化与失败恢复。逐项记录准确版本及证据；失败先修复复验，用户负责最终核验，不承担首轮测试。设计→实现→真实视觉交互自验→用户核验是同一功能闭环；编译或静态审查不替代渲染、键盘焦点、VoiceOver 和窗口缩放检查。现已收到独立合成环境 GUI 自验许可，但缺可用原生 macOS 控制工具，这些检查保持未验，不把任务转给用户。通用模板由原负责流程统一承载，本节仅为本项目接入条件。
