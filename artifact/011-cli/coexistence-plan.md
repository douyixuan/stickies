# App 与 CLI 并用方案（设计候选，尚未实现）

## 当前缺口

当前所有数据命令都要求 App 正常退出。锁拒绝测试只证明安全拒绝，不代表完整 CLI 产品验收。
本方案不改变当前安装，不启用 GUI 自动操作，不访问真实便签，不开启网络服务。

## 唯一存储权威

App 运行时持续持有 notes.lock。所有 CLI 请求交给现有 MainActor NoteStore，不能另读磁盘作为实时结果。
正文输入、同步回调和 CLI 变更在同一执行序列中完成。读取命令返回该序列中的内存状态，包括尚未保存的编辑。
变更命令在持久化成功后才能返回成功。保存失败必须恢复内存候选或明确保留待保存状态，不能错误确认成功。
当前 updateText 先改内存再调用私有 save，且不向调用者返回保存错误，不足以直接提供此保证。先提取可返回错误的共享命令执行层。
CLI 在 App 关闭时持锁使用同一执行层，继续保留兼容字段和本机 Trash 语义。

## 本机请求通道

优先评估数据目录中的私有文件请求队列，不使用 TCP、HTTP、远程地址或后台系统服务。
App 仅在成功获得现有锁后发布本次运行的会话标识。会话标识用于识别过期请求，不作为凭据。
目录要求当前用户所有、0700权限、无符号链接；文件要求常规文件、单链接和大小上限。
CLI 完整读取 stdin 后原子提交请求。App 校验协议版本、会话、请求 ID、命令和参数后串行执行。
App 的关闭流程先停止接受请求，再完成已接收操作并释放锁。CLI 不自动启动或退出 App。
旧版 App、不支持协议、队列拥塞、超时及过期会话均明确拒绝；不能在持锁期间回退到直接存储操作。

文件队列只能防误用，不能防同一用户账户下的恶意进程。实现前必须审查路径竞争及清理策略。
如现有沙盒或签名要求新权限、App Group 或其他能力，先报告阻点，不擅自配置。

## 崩溃与重试契约

变更请求包含固定请求 ID。默认不自动重发可能已执行的操作。
仅写响应文件不足以保证崩溃后恰好一次执行。必须先确定请求结果与数据写入的共同提交边界。
优先验证原子快照或可恢复事务记录与现有兼容格式的关系，再决定协议。
未获得可靠提交证据时返回明确的结果未知状态，不能宣称未修改或成功，也不能自动重试 add/delete。
会话重启后的残留请求不自动执行。该契约及未知状态退出码需要在实现前固定并更新 CLI 文档。

## 隔离验证顺序

1. 使用临时目录及无窗口 NoteStore 宿主，覆盖实时读取未保存编辑和 CLI 成功后的重新加载。
2. 同时提交编辑、同步更新和多进程 CLI，证明顺序明确且没有覆盖较新正文。
3. 注入 notes.json/trash.json 读写失败，核对错误分类、内存状态、磁盘哈希及无部分批量结果。
4. 在接受、应用、持久化及响应各阶段结束宿主，核对恢复、重复请求和结果未知语义。
5. 覆盖旧版宿主、会话更换、队列满、超限输入、路径链接、错误所有者及关闭竞争。
6. 独立 review 后运行 CI。只有合法 GUI 路线具备时，再做真实窗口与 CLI 并用验收。

在上述事务边界及故障测试完成前，本方案不能标记为实现完成或批准安装。
