# 紧凑头部修复与审查

用户反馈：顶部太高，但完全没有头部不易拖动。已通过 Library 官方助手下载截图并查看实际像素（本地 build/header-reference/user.png）。原图 260×220，白色标题栏约 32pt，加独立菜单行后正文约从 70pt 开始。

方案：保留 AppKit 原生标题栏和关闭/缩放/最小化、键盘 Notes 菜单。标题文字视觉隐藏但保留窗口可访问标题。两个既有菜单移动到 22pt 高的原生标题附件；没有增加新功能。背景与便签同色，去掉第二工具行，正文起点约 44pt。原生较宽拖拽命中区保留；细握柄位于 24×22pt 附件，仅该区域调用原生 performDrag。按钮在悬停时加深、平时低强调且仍可发现。正文完全不接收窗口拖拽。

独立审查：完整重读差异，检查窗口附件生命周期、palette 颜色一致性、原生关闭/键盘路径、正文选择与窄窗口重叠。发现失焦窗口的握柄首次鼠标事件可能只激活窗口，增加 acceptsFirstMouse=true，仅限握柄，未改变文本响应。无存档 schema 或正常存档路径变化。

验证：本机编译、布局与 AppKit 存档/恢复/置顶/最小化/锁测试通过；180pt 窄窗口两个附件不相交，标题区没有额外行，isMovableByWindowBackground=false。真实 UI 输入和选择 Select this text normally. 成功，截图中灰色选择/失焦控件与细握柄仍可见。真实标题握柄拖拽再次被 CUA 外部窗口变化保护中止；最小窗口实机截图请求 timeoutReached。未把这些尝试写成通过，不继续无界调试。
