# 持锁命令核心候选

目的：在没有传输服务、没有 GUI 操作、没有新权限的条件下，先验证 App 与 CLI 并用需要的存储权威和幂等提交。
本切片不让当前 istk 连接运行中的 App。当前 CLI 仍在锁冲突时返回75，不能称为并用产品验收完成。

## 执行边界

NoteStore.executeCommand 在 MainActor 同步执行，不跨 await。额外重入标志拒绝发布回调嵌套命令和编辑。
list 返回当前内存，包括保存失败的编辑。变更要求持锁、Trash可用且不存在未保存编辑。
支持 add/edit/delete/restore；新建默认隐藏，不创建窗口。批量参数先完整校验。
命令只在持久化完成后发布内存和成功结果。提交前失败不改变内存或已保存内容。

## 提交与去重

command-journal.json 原子记录完整 notes/trash/result ledger 后镜像及之前文件的摘要。这是请求接受点。
接受后的失败表示需要恢复，不能声称未修改。App 冻结编辑和所有变更入口，保留日志并允许正常退出。
下次持锁 App 或 CLI 先恢复，再加载状态或处理命令。恢复逐文件原子写入，最后移除日志。
启动恢复会在任何写入前核对三个文件均匹配前镜像摘要或后镜像。外部变更不匹配时停止，不覆盖。
日志损坏、异常文件或恢复失败时保持只读。不能用旧版本打开待恢复数据；旧版本没有恢复协议。
此实现验证进程崩溃，不承诺断电后 fsync 级别的持久性。

command-results.json 保存请求ID、参数指纹和原结果。相同请求重放返回原结果，不重新修改最新内容。
相同ID与不同参数冲突时拒绝。读取不缓存，其ID不占用变更去重空间。
最多4096条变更结果，不自动驱逐；容量满后拒绝新变更，仍允许查询原请求和读取。
文件与日志上限64MiB，正文上限8MiB；当前没有结果清理或日志压缩协议。
本机 delete/restore 保留 notes.json 原字节，并保留同步身份。恢复不回滚更新后的正文。

## 后续接线前门槛

本切片没有请求监听器、套接字、文件队列轮询、后台服务或新签名能力。
实际连接CLI前，必须完成有界请求通道、会话、超时取消、结果查询、响应保留和权限审查。
所有涉及新增权限、持久访问或安全设置的步骤先报告，不能自行启用。
真实窗口并用、两台Mac和云传输继续由批准后的QA路径验收。禁止中间安装。
